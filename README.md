# jinja-instagram

神社アプリ Instagram アカウント用のカルーセル投稿画像を制作するプロジェクト。

## 目的とストーリー

単なるアプリ宣伝ではなく、**神社様からDMで問い合わせをいただくこと**が最終目的。
最初の3投稿は「アプリ紹介 → 電子御朱印の構想 → 神社様募集」というストーリーになっている。
それ以降は「地域紹介」「機能紹介」「地域別の神社様募集」を組み合わせたカレンダーとして追加している。

| # | 投稿 | 種類 | ねらい |
|---|---|---|---|
| ① | 北海道の神社、何社知っていますか？ | 地域紹介 | アプリそのものを知ってもらう |
| ② | こんな電子御朱印を作りたい。 | 開発ストーリー | 電子御朱印構想を、開発中と正直に伝える |
| ③ | 北海道の神社様へ。 | 神社様募集 | 掲載・電子御朱印パートナーをDMで募集 |
| ④ | 東京都の神社、何社知っていますか？ | 地域紹介 | アプリの認知を東京エリアに広げる |
| ⑤ | 京都府の神社、何社知っていますか？ | 地域紹介 | アプリの認知を京都エリアに広げる |
| ⑥ | 大阪府の神社、何社知っていますか？ | 地域紹介 | アプリの認知を大阪エリアに広げる |
| ⑦ | 福岡県の神社、何社知っていますか？ | 地域紹介 | アプリの認知を福岡エリアに広げる |

## 素材の原則（重要）

**架空のアプリ画面・架空の電子御朱印デザイン・架空の神社情報は一切使用していません。**
すべての画面キャプチャは、実際に公開されているアプリ
（https://shrine-map-zeta.vercel.app）から取得した本物のスクリーンショットです。

- 電子御朱印そのもののデザイン画面はログインしないと確認できないため、投稿②では「現在、開発中です」という正直な切り口にしている
- 地域名（東京・京都など）で検索しても実装上ヒットしないことがあるため、④〜⑦・⑪〜⑬では実際にその地域の神社「名称」で検索した本物の結果を使用している（例：東京＝明治神宮、京都＝下鴨神社、大阪＝住吉大社、福岡＝太宰府天満宮）
- 検索結果の「◯件を表示」のような件数表示は、少なく見えて誤解を招かないよう画面をトリミングして含めていない

デザイン方針：日本らしく、上品で、清潔感・信頼感があり、神社関係者が見ても違和感がなく、
若い Instagram ユーザーにも魅力的で、広告っぽくなりすぎない／安っぽい AI 感を出さないこと。

## フォルダ構成

```
jinja-instagram/
├── posts/                          投稿ごとのスライド（本体、投稿①〜⑬）
│   └── postN_xxxxx/
│       ├── content.js              ← 文章はここを編集する
│       ├── slide1.html             1枚目
│       ├── slide2.html             2枚目
│       ├── slide3.html             3枚目
│       └── slide4.html             4枚目
│
├── shared/                         全投稿共通のデザイン・仕組み
│   ├── styles.css                  配色・フォント・共通パーツのCSS
│   └── apply-content.js            content.js の文章を画面に反映する仕組み
│
├── assets/images/                  実際のアプリから取得したスクリーンショット
│   └── postN_xxxxx/                投稿ごとの画像 + README.md（用途の説明）
│
├── export/                         PNG書き出し先（post1/ 〜 post13/、各4枚）
│
├── scripts/
│   ├── fetch-app-screenshots.js    投稿①〜③用：実際のアプリから画面を取得
│   ├── fetch-more-screenshots.js   投稿④〜⑬用：実際のアプリから画面を取得
│   ├── export-to-png.js            HTML → PNG 一括変換スクリプト
│   └── check-slides.js             全スライドの自動チェック（文字のはみ出し・画像切れ）
└── package.json
```

## 1. スライドを確認する

プロジェクトルートで簡易サーバーを立てて確認するのが確実です
（`file://` で直接開くとブラウザによって `content.js` が反映されないことがあるため）。

```bash
python -m http.server 8000
```

起動後、`http://localhost:8000/posts/post1_hokkaido-shrines/slide1.html` のように開けます
（フォルダ名は `posts/` 配下を参照してください）。

サイズは 1080×1350px 固定でデザインされています（Instagram縦型カルーセル比率 4:5）。

## 2. 文章を編集する

各投稿フォルダの **`content.js`** に、その投稿4枚分の文章がまとまっています。
デザイン（レイアウト・色・フォント）を触らずに、ここの文字列を書き換えるだけで
対応するスライドの表示が自動的に変わります。

```js
// 例：posts/post1_hokkaido-shrines/content.js
slide1: {
  title: '北海道の神社、\n何社知っていますか？', // \n で改行
  subtitle: '地図を開くと、\nまだ知らない神社に\n出会えるかもしれません。',
  ...
}
```

- `series` はそのシリーズ共通の見出し（左上の小さなラベル）です。1箇所編集すれば4枚すべてに反映されます。
- 改行したい位置には `\n` を入れてください。
- 数字や統計（「北海道には○○社あります」等）は、実際のアプリで確認できない限り書かないでください。
- 文章を長くしたときは、下記の `npm run check` で文字がフッターにかぶっていないか確認してください。

## 3. 実際のアプリ画面を取得する

Node.js が入っていれば、以下のコマンドで実際の公開アプリ
（https://shrine-map-zeta.vercel.app）から画面を撮影し、`assets/images/` 配下に保存できます。

```bash
npm install
npm run fetch-screenshots
```

投稿①〜③分は `scripts/fetch-app-screenshots.js`、投稿④〜⑬分は
`scripts/fetch-more-screenshots.js` が担当しています。取得元のURLや対象神社は
各スクリプトの先頭で変更できます。アプリの見た目が変わった場合は再実行すれば
画像が最新の状態に更新されます。各 `assets/images/<投稿フォルダ名>/README.md` に、
ファイルごとの用途も記載しています。

## 4. デザインを調整する（共通デザイン）

配色・フォント・余白・共通パーツ（キッカー、ページ番号、フッターロゴ、実機スクリーンショット用の
カード・電話フレーム、開発中バッジ、約束パネル、DM訴求ピルなど）はすべて `shared/styles.css` に
まとまっています。ここを直すと全投稿・全スライドに反映されます。

特定のスライドだけ微調整したい場合は、各 `slideN.html` 内の `<style>` や
インラインスタイルを編集してください。

## 5. 全スライドをチェックする

```bash
npm run check
```

52枚（13投稿 × 4枚）すべてを自動で開き、文章がフッターにかぶっていないか、
画像が壊れていないかをチェックします。`content.js` の文章を大きく書き換えた後に
実行すると安心です。

## 6. PNGに書き出す

```bash
npm install
npm run export
```

`export/post1/` 〜 `export/post13/` に、各投稿4枚ずつ
1080×1350px の PNG が書き出されます（そのままInstagramに投稿できるサイズ）。
